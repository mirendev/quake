# Contributing to Quake

Thank you for your interest in contributing to Quake!

## Project Scope

Our development priorities are focused on our own use cases. We're happy to accept contributions that align with our goals, but we may decline PRs that add features we don't need or that would increase our maintenance burden.

## How to Contribute

### Reporting Issues

If you find a bug or have a question, feel free to [open an issue](https://github.com/mirendev/quake/issues). We'll do our best to respond, though our capacity may be limited.

### Pull Requests

Before starting work on a significant change, please open an issue to discuss it first. This helps avoid wasted effort on changes we might not be able to accept.

For small bug fixes or documentation improvements, feel free to submit a PR directly.

### Development Setup

1. Clone the repository
2. Run tests: `go test ./...`
3. Build: `go build .`

Please review our [Code of Conduct](CODE_OF_CONDUCT.md) before participating.
